# «Смачно» — вебзастосунок замовлення страв

Навчальний проєкт за темою **«Вебзастосунок замовлення страв», Варіант 11**. Інтерфейс і повідомлення застосунку подано українською мовою.

## Можливості

- Перегляд меню за категоріями, пошук страв за назвою, описом і складом.
- Перегляд складу, довідкової інформації про алергени та доступних модифікаторів.
- Кошик зі зміною кількості, вибором модифікаторів і часового інтервалу отримання.
- Реєстрація клієнта, вхід, перегляд історії та скасування власного нового замовлення.
- Панель оператора для перегляду замовлень, оновлення статусів, керування доступністю страв і прийманням замовлень.
- Перевірка даних, цін і прав на сервері; база даних SQLite.

## Вимоги

- Python 3.10 або новіший.
- Сторонні Python-пакети для роботи застосунку не потрібні.
- Для перевірки синтаксису JavaScript потрібен Node.js.

## Запуск у Windows

Запустіть сервер:

```powershell
python run.py
```

Відкрийте у браузері <http://127.0.0.1:8000>. Щоб зупинити сервер, поверніться до вікна PowerShell і натисніть `Ctrl+C`.

Під час першого запуску програма створює папку `data`, файл `data/orders.sqlite3`, початкове меню та часові інтервали. У застосунку перейдіть до розділу входу та створіть обліковий запис оператора. Початкове створення оператора доступне лише тоді, коли в базі ще немає оператора.

Для перевірки клієнтського й операторського облікових записів використовуйте два різні профілі браузера, наприклад звичайне та приватне вікна або два різні браузери. Звичайні вікна одного браузерного профілю можуть використовувати спільні cookie й сесію.

## Автоматизоване тестування

Запускайте тестовий набір **із кореневої папки проєкту**, а не відкривайте `tests/test_app.py` окремо:

```powershell
python -m unittest discover -s tests -v
```

Модульний запуск (`python -m unittest ...`) знаходить імпорт `app.py` у корені проєкту й автоматично запускає тести з папки `tests`. Успішне виконання завершується рядком `OK`; кількість виконаних тестів вказана у підсумку.

Тести створюють окрему тимчасову базу SQLite для кожного сценарію й видаляють її після завершення. Вони не очищають і не змінюють основну базу `data/orders.sqlite3`.

Набір перевіряє:

1. Серверний розрахунок вартості та ідемпотентність повторного підтвердження замовлення.
2. Заборону клієнту позначати своє замовлення як виконане.
3. Відхилення оформлення, якщо заклад не приймає замовлення.
4. Відхилення страви, яку оператор позначив недоступною.
5. Контроль місткості часового інтервалу.
6. Обмеження кількості модифікаторів однієї страви.
7. Заборону клієнту змінювати меню через операторський API.
8. Одноразове початкове створення облікового запису оператора.

Додаткові перевірки синтаксису:

```powershell
python -m py_compile app.py app_common.py database.py orders.py run.py tests\test_app.py
node --check static\app.js
```

## Ручна перевірка у браузері

1. Запустіть програму й відкрийте <http://127.0.0.1:8000>.
2. Перевірте, що відображаються категорії меню, страви, ціни, склад, алергени та модифікатори.
3. Знайдіть страву через пошук і перемкніть категорію меню.
4. Додайте страву до кошика, виберіть модифікатор і перевірте зміну попередньої суми.
5. Створіть обліковий запис клієнта, виберіть доступний інтервал і оформіть замовлення.
6. Увійдіть як оператор в іншому браузерному профілі; перевірте появу замовлення та послідовно змініть його статус.
7. Поверніться до клієнтського профілю й перевірте оновлення статусу в історії замовлень.
8. Як оператор, тимчасово вимкніть доступність страви або приймання замовлень. Перевірте, що оформлення такого замовлення відхиляється; після перевірки поверніть потрібні налаштування.
9. Переконайтеся, що клієнт не може виконувати дії оператора, а зміни залишаються після перезавантаження сторінки.

Список замовлень в авторизованому інтерфейсі оновлюється періодично. У разі проблеми із завантаженням перевірте, що сервер працює, та перезавантажте сторінку.

## Файли проєкту

- `run.py` — точка запуску локального WSGI-сервера.
- `app.py` — серверні маршрути та обробка запитів.
- `app_common.py` — спільні типи помилок, стани замовлення та JSON-відповіді.
- `database.py` — схема SQLite, ініціалізація початкового меню та інтервалів.
- `orders.py` — робота з меню, інтервалами та бізнес-правилами замовлень.
- `templates/index.html` — структура вебсторінки.
- `static/app.js` — клієнтська логіка інтерфейсу.
- `static/styles.css` — стилі й адаптивне компонування.
- `tests/test_app.py` — автоматизовані тести.

## Дані й обмеження

База зберігається у `data/orders.sqlite3`. Вона містить облікові записи, налаштування та історію замовлень, тому не додавайте її до репозиторію й не видаляйте, якщо потрібно зберегти ці дані. Папки `data/` і `__pycache__/`, а також файли `*.pyc` виключено у `.gitignore`.

Для окремого розташування бази можна перед запуском задати змінну середовища:

```powershell
$env:DATABASE_PATH = "C:\шлях\до\orders.sqlite3"
python run.py
```

Застосунок є навчальним локальним проєктом. Він не включає онлайн-оплату, доставку або інтеграцію з касою; стандартний сервер розроблення не призначений для публічного виробничого розгортання.
